# v4.2.7 / Step16 验收记录

## 任务与技术设计

在已发布Step15基础上增量实现Zotero标准批注双向同步；只同步标准批注，不同步私有手写或Markdown正文。复用ZoteroClient、原件授权/内容哈希、完整来源身份、ZoteroSessions、既有只读缓存、RevisionMetadata与稳定资源ID。schema20三个附加表保存当前意图、独立处理修订和来源刷新设置；没有第二套Markdown服务、新全局状态框架或新第三方依赖。

六状态SYNCED/LOCAL_DIRTY/REMOTE_CHANGED/CONFLICT/FAILED/READ_ONLY，严格类型main-only IPC与本地CAS；首次落盘固定创建key，发送前保存待复核标记，重启先按同一key读取。失败和冲突保留基线、本地与远端，处理边界保存不可变修订；普通键入和无变化轮询不堆积历史。自动刷新默认关闭，0/30/60/300秒，只读GET，隐藏/输入/忙碌跳过、失败暂停。手动同步主动确认并列出删除key，不自动申请权限。

冲突解决重新读取并检查展示版本；采用本地只重新排队，再显式提交，远端已删除不自动复活。关闭前等待本地落盘，恢复后不恢复密钥。库、附件、实例与PDF摘要变化阻止越界操作；个人/群组与非作者权限由Zotero权威检查。

## 原始失败与修正

普通沙箱执行曾出现临时文件ENOENT及原子提交拒绝访问，保留日志后在真实Windows环境重跑。旧schema19/未来20断言完整升级到当前20/未来21，未删除断言。Clippy两个新代码风格错误正常修正。真实Zotero在准备后目标被删除时PATCH返回400；产品只有另行来源校验GET404证实删除后才判NOT_FOUND，其他400保持参数错误。

首轮原生批次复用证据目录被EEXIST保护拒绝，换新run ID完成；未删除旧证据。旧写入测试无实际内容变化，被新幂等逻辑识别为已一致而未发送412请求，测试改为先修改评论；旧删除测试选择了仍有待处理冲突的同一条记录，产品保留该输入，测试改为选择另一条无待处理记录的专用便签，继续验证确认与404。扩展定位通过专门wrapper补跑25项，而非用基础15项冒充。
