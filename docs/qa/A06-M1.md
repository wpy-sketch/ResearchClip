## 2. 实际实现入口

- storage/library.rs：截图CAS、物理删除、pending_file_deletions完成后清除；notes和tags基础访问。
- storage/projects.rs：项目/批量删除、Markdown canonical path登记、同名约束。
- storage/revisions.rs + migrations/005_annotation_revisions.sql：全局形状的revisionId可复用，但version_number是单机序号，当前head依赖MAX。
- services/markdown_document.rs：外部标准.md、内存文件授权、原字节冲突校验、受管PNG相对资源；不是数据库正文和完整图片资源索引。
- storage/knowledge.rs：卡片UI主笔记与其他笔记并存；同步不能只取主笔记。
- storage/files.rs：受管原PNG、路径根检查、大小与禁止覆盖写入可复用。
- storage/clips.rs / browser-extension：现有网页剪藏协议独立，不提供WebDAV写SQL入口，不应修改浏览器扩展来充当同步客户端。

## 4. 八项审计与复现

| 检查 | 实际结果 | 复现/观察 |
| --- | --- | --- |
| schema5基础与原图引用 | PASS | 应用现有001–005；编辑JSON后原PNG字节相同，外键有效 |
| 单端修改 | PASS（审计） | A从1变2，B仍1；仅说明单端差异可见，不代表同步成功 |
| 双端修改同一标注 | PASS（风险复现） | A/B各自产生不同JSON的v2和相同截图revision2；将B历史直接插入A触发UNIQUE(screenshot_id,version_number) |
| 删除完成无持久同步意图 | PASS（风险复现） | A物理删除卡片、历史/notes级联，确认文件清理队列后无tombstone；B仍持旧卡片。缺失行不能区分“从未加入”和“明确删除” |
| 同名Markdown跨设备身份 | PASS（风险复现） | A/B同名.md和相同正文，canonical path与独立登记的ID不同；不能以名称或路径自动合并 |
| 外部正文/assets变更 | PASS（风险复现） | 文件变化后markdown_documents行/updated_at不变，且无content_hash、revision、deleted_at列 |
| 同名不同ID的标签/项目 | PASS（风险复现） | 直接插入相同normalized_name的新ID触发约束，不能REPLACE覆盖既有资料 |
| 共享标签与项目范围 | PASS（风险复现） | 已选项目与未分类卡片共享标签；修改标签名称会同时改变未分类卡片显示，必须提前说明并保护跨范围删除 |

### 同步风险严重程度

- A06-M1-01 / P0风险：若把列表缺失当作删除或用LWW覆盖，可能丢资料或复活已删资料；没有发生于当前单机应用，本轮也未实现这种算法。
- A06-M1-02 / P1：单机revision/标注显示ordinal无法作全局版本，直接历史合并稳定触发约束；需明确head与全局revision映射。
- A06-M1-03 / P1：外部Markdown身份、字节快照与资源授权不足，直接迁移路径会失效；未同步外部文件以避免越权。
- A06-M1-04 / P1：同名约束与共享标签必须先定义冲突/范围策略。

预期的UNIQUE错误是审计复现成功，不是已运行SyncEngine失败，也不是v1.0.5本地功能崩溃。当前没有未解决的审计脚本FAIL；**同步就绪结论仍为BLOCKED。**

## 6. Windows人工验收清单（均NOT_RUN）

1. 测试账户仅访问专用空测试目录；在设置安全入口输入凭据，确认文件/日志无密码或用户名泄漏。退出重启仍可读取凭据，删除连接时明确处理凭据。
2. 连接测试显示实际服务器能力；弱ETag/忽略条件头时写入按钮禁用，不能仅依据服务器品牌放行。
3. 预览项目及文档/图片数量、共享标签影响、外部文档授权；取消不上传、不写本地或远端删除。
4. 两台设备完成初始/单改/双改/删除修改/重名及所有标注历史同步；切换当前版本、编辑、保存和原分辨率PNG均正常。
5. 标准.md与相对assets在另一台机器及外部Markdown软件打开，中文/LaTeX/换行源码不变，缺失图片有错误而非静默成功。
6. 断网、停止、任务中退出、重新启动、再次同步；进度和状态与文件实际一致，冲突双方均可恢复读取。
