# 分阶段开发与验收计划

总体原则：Windows 10/11 x64 优先；每阶段可运行、可验证；数据与文件始终本地保存；原图不可变；有失败路径和测试证据后才宣布完成。下列阶段并非本轮已授权实现范围。本轮止于 M1。

| --- | --- | --- |

| M2 Windows 采集与保存 | 原生捕获实验→单屏框选；全局热键；Esc 取消；PNG 原图落盘；基础卡片建立；可选图片导入 | 单屏100/125/150/200% DPI 和混合 DPI 多屏分别框选、负坐标/旋转边界不越界；快捷键冲突可见；取消无文件/卡片；保存失败不留半卡；重启可见图像；原图像素尺寸准确 |

## M1 具体边界

已实现的图像工作台只用于确认 Konva 能挂载和响应容器尺寸，没有图片导入、画图事件、保存按钮或截图行为。卡片库是零卡片空状态，搜索和未来功能按钮禁用。工作区设置为只读诊断。SQLite 仅有 app_metadata 表，不提前铺设空 CRUD 服务。

M1 不包含安装包、自动更新、系统托盘、OCR、云同步、PDF 导入、参考文献连接、AI 标注或外部账号。原生截图适配器不以返回假图的 stub 实现，不注册仍无作用的全局快捷键。

## 关键风险与先决实验

1. M2 开始先验证显示器帧读取、主窗口隐藏与混合 DPI。锁定 Windows API/Rust crate 前以安装版本源码及最小实验确认签名，不编造 screenshot 命令。
2. M3 开始先锁定 annotation v1 规范和纯坐标变换函数，再接 Konva 编辑行为。导出与恢复必须来自同一文档。
3. M4 在小规模直接查询与真实中文资料上量测检索效果。搜索性能需求为阶段验收指标，不能从技术栈名称推断吞吐量。
4. M5 演练 SQLite + 原图恢复；WAL 在线备份不能直接复制一个主库。安装程序删除应用不得默认删除研究资料。
5. M6 用真实 Mac 决定最低系统版本，保持 Windows 原生实现隔离于平台模块，不在 React 里判断 OS 后硬编码原生行为。

## 检查与交付习惯

- 每阶段记录范围、依赖版本、执行命令、退出码、测试数量、原生手动/自动运行证据、未通过项。
- 前端关键测试覆盖 IPC 形状、预览分支、错误与重试、并发初始化；Rust 测试使用真实临时 SQLite 和 Unicode 路径。
- Native 冒烟负责完整链路：exe → WebView2 → React → IPC → SQLite。浏览器通过不能代替桌面验收。
- 未来截图验收另做硬件矩阵：显示器数量、DPI、旋转、GPU、HDR、远程桌面。自动测试无法覆盖的条件必须明确列为未验证。
- 依赖锁文件入库，生成物、工具链、用户资料不入库。任何未执行检查标为“未执行”，失败标为“失败/受阻”，不写“应该通过”。

M1 完成后停止，由下一轮单独推进 M2。
