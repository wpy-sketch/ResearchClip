## 2. 共用验收方法

每阶段记录：代码/依赖版本、执行命令、退出码、通过/失败用例、机器OS/CPU/RAM/GPU、显示器分辨率/DPI/布局、原生证据、未执行项和未解决问题。记录写入该阶段验收报告，不覆盖M1历史事实。

自动测试覆盖确定性规则和失败注入；native冒烟验证实际exe与IPC；截图正确性必须使用真实显示器和已知像素测试图。测试使用临时数据库与独立测试工作区，不清空真实AppData。故障注入使用测试路径，不断电破坏用户资料。

性能数字是**首发目标**，不是已有结果。参考环境为Windows x64、本地SSD、至少4个逻辑核心/8 GB RAM、一个SDR 3840×2160显示器；测试记录真实硬件。预热5次后测50次，按nearest-rank计算p95（排序后第48个样本），同时保留最大值、失败次数和原始数据。不以平均值替代p95；失败的功能用例不能从正确性门槛中剔除。

| 测量项 | 目标 | 起止点 / 数据集 |
| --- | --- | --- |
| 区域截图准备 | p95 <=1,500 ms | 快捷键回调到冻结帧/覆盖层可交互，4K SDR |
| 截图落盘/建卡 | p95 <=2,000 ms | 有效选区提交到PNG落盘与SQL提交完成；全屏含等效保存步骤 |
| 搜索 | p95 <=250 ms | Rust收到查询到返回第一页50张卡，1000卡/每笔记约2 KiB/中英文标签 |
| 搜索UI更新 | p95 <=500 ms | 用户提交查询到结果列表可交互，排除人为输入debounce等待 |
| 数据保存 | p95 <=500 ms | 保存普通笔记或100图元文档到DB提交；不含PNG渲染 |
| 合成导出 | p95 <=3,000 ms | 已加载4K图/100图元到PNG编码及文件完成，字体已就绪 |

不满足目标应记录结果、原因和优化/调整建议；不能单方面删掉目标或降低质量。资源上限按PRD执行，超过上限返回错误而非崩溃。

## 5. M2A：Windows原生捕获实验

只验证平台路线；UI和业务保存不随实验扩张。输出原生依赖版本/API出处、显示器/坐标单位、帧格式/颜色/旋转、线程模型及错误报告。

通过条件：

- 真实读取每个测试SDR显示器的帧，尺寸与系统物理分辨率一致；测试图角落/边缘色块匹配，冻结画面来自屏幕而非fixture。
- 静止桌面能取得有效帧或在2秒预算内返回TIMEOUT；空缓冲不算成功。
- 定义并验证原生帧释放与取消；连续50次捕获完成，无遗留捕获会话/资源句柄的持续增长。
- 检查主窗口隐藏后没有自身窗口/未来覆盖层进入原图；数据明确是不含光标的sRGB SDR。
- 对无法访问的桌面、设备丢失/显示器消失给出分类错误；模拟错误单测标记为mock，锁屏/远程等真机不可测时记录未验证。
- 编译、相关Rust测试/clippy通过；实验未通过前不选择生产wrapper或宣称F02可用。

若候选DXGI路线在基本场景受阻，记录错误与复现条件，再提出替代原生路线。替代需要独立实验；不同时铺设多个框架。

## 6. M2B：全屏/区域、热键和原图保存

范围是F01/F02以及基础asset/card保存。拟新增v2迁移：image_assets/cards；迁移必须保存v1元数据。单实例/热键生命周期在这一阶段接入；托盘菜单在M5。

### 正常功能门槛

- 菜单与快捷键都能捕获指定显示器完整画面或目标屏区域，产生一张PNG和一张卡片；卡片默认非空标题、尺寸、hash、来源metadata准确，重启可读取。
- 快捷键Pressed/Released序列一次产生一个会话；连续按下时无第二会话、无重复卡片。冲突提示；修改失败保留旧有效配置。
- Esc/空选区在saving之前取消，无新卡片/原图；窗口状态恢复。saving期间取消按ARCHITECTURE的提交边界返回明确终态。
- 文件不存在/目录不可写/磁盘满/SQL失败/UUID目标碰撞均不覆盖旧文件，不留引用不存在图片的“成功卡片”；失败保留可诊断信息。
- 第二实例激活第一实例，不能再注册热键或写同一工作区。真正退出注销热键。

### 显示器验收矩阵

每个可支持组合用至少10个已知边界选区检查，裁切尺寸正确，四边误差均<=1物理像素。实际设备上变更缩放后按系统要求重启/重新枚举再测，不能只改变浏览器zoom。

| 场景 | 必测内容 |
| --- | --- |
| 单屏100%、125%、150%、200% | 全屏、四角/边缘、反向拖动、1像素小选区 |
| 双屏100% + 150%，100% + 200% | 分别选每屏；鼠标所在屏与固定屏策略；没有全局单一scale造成的偏移 |
| 第二屏在主屏左侧/上侧 | 负原点、窗口位置与局部裁切坐标 |
| 横屏与90度竖屏 | 转正后的frame尺寸、上下/左右边缘 |
| 捕获中拔出屏幕或变更DPI/分辨率 | 取消旧会话并恢复；不提交旧坐标 |
| 跨屏拖动 | 限定目标屏边界，UI不承诺拼接 |

缺少任何必测硬件组合时该矩阵未全通过，必须列为发布阻塞或获得用户明确调整支持范围；不能静默跳过。计时达到共用表的准备/落盘目标。

## 7. M3：五种无损标注、撤销/重做和图片导出

F03/F04。拟v3迁移新增annotation_documents，为已有卡片建立匹配原图的空文档；M3后采集建卡同时建立文档。

通过条件：

- 箭头、矩形、椭圆、文字、自由画笔均可创建、选择、移动、删除、改基础样式；中英文/换行文字保存后可读。所有图元能保存、重开、再次编辑。
- 25%、50%、100%、200%编辑缩放及pan后，坐标往返误差<=0.5原图像素；任何视口缩放不改写原图或图元坐标。
- 100个普通小对象编辑操作全部撤销/重做后文档与快照一致；一次拖动/笔画仅一条记录；撤销后新编辑清空redo；32 MiB预算超限按PRD处理。
- 保存后继续编辑、撤销回保存点的脏状态正确；冲突、未知schemaVersion/图元、超上限文档均拒绝覆盖并保留用户草稿。
- 关闭/换卡/截图/退出时“保存/放弃/取消”均验证，保存失败不可丢草稿；可重复执行的失败路径有测试。
- 原图hash在编辑、undo/redo、保存、重启和两种PNG导出后不变；输出PNG尺寸等于原图物理尺寸，且不含选框/工具栏/viewport变换。
- 合成PNG和编辑画面来自同一已保存文档；真实标注测试图的锚点偏差<=1像素，透明度/图层/文字布局一致，原图导出字节保持一致。
- 非法尺寸/stride、单图16,777,216像素、2,000图元/100,000画笔点、8 MiB文档等边界测试通过；拒绝后应用继续工作。
- 对应TS/Rust测试、构建与native冒烟通过，保存/导出计时达到共用目标。
