# v4.2.4：PDF与Markdown双向定位（先行设计）

基线为v4.2.3的既有PDF.js6.4.299阅读器、统一PdfLocation（附件ID/内容哈希/物理PDF点）、摘录写入意图、Markdown相对图片和链接索引。只实施用户本轮请求，不开发批注写回或后续业务；无新依赖、原始PDF写入、第二正文或全局身份系统。

## 复用与变更

1. 点击截图：从已有v1图文组边界和受控pdf-location链接解析对应位置，图片按钮走pdf.navigateTo，编辑草稿与原光标保留。普通图片仍普通显示，不从文件名猜测来源。
2. 来源定位：按稳定位置ID获取文档、附件和哈希；每次跳转重新核对受管PDF字节，已打开标签也不跳过验证。明确拒绝内容替换、页面越界或几何不匹配。使用当前页物理坐标映射，临时高亮自动消退，保留当前旋转及缩放；目标矩形滚动到可见区域。
3. 反向查找：扩展已有Markdown链接解析/后台worker和同一CAS索引事务，pdf-location条目进入schema18派生表pdf_note_links，沿用现有link_index_state和文档稳定ID。普通文档/截图知识图谱仍用原link_index。按附件、哈希、页码和矩形相交检索；结果提示未索引/过期和草稿，不把未保存笔记说成已持久化。
4. 文字引用：读取当前PDF文字层真实选区和Range矩形，经过PDF.js viewport映射为同一PdfLocation，可保存多行矩形和exact文本锚点。不截图、不OCR、不改写PDF；拒绝跨页、无权限或超预算选区。插入Markdown沿用DocumentStore局部编辑和撤销，纯文字引用也有稳定返回链接。
5. 元信息：来源标题、零基存储/一基显示页码、已确认的Zotero library/item/attachment信息，普通PDF明确未关联，不推断或伪造。

## 文件移动与版本

阅读器已有受管只读副本按SHA256命名，原始PDF改名或搬移不改变引用。用户重新选择相同内容时沿用稳定资源ID和单一标签；不同内容创建不同附件/文档，不把旧引用转接到新版本，不自动猜测新增页面偏移。不修改Zotero PDF来维持引用。失效来源明确提示，重新授权/重新摘录需用户操作。

schema18只增加派生索引，001–017不可修改；沿用事务、一致快照、未来版本拒写。旧文档通过已有“更新当前索引”或保存重建派生索引，源码、旧截图和旧链接不改写。失败保留旧索引并报告；过期结果不得用旧偏移覆盖草稿。

## 验收与回退

单元覆盖源文保真、围栏排除、分组定位、UTF16偏移、矩形相交、旋转及不同面板尺寸、临时高亮生命周期和失效拒绝。隔离SQLite演练17→18及旧PNG/Markdown/来源完整性；实际Windows验证截图点击、重复打开、多PDF、文字选区、双向查找、重命名/移动/替换和重启。物理多屏与真实Zotero UI继续独立人工验收。

关闭双向面板可继续普通阅读与Markdown编辑；派生索引失败不删除正文或截图；格式未知保留原文。旧程序不写18库，回退须使用迁移前一致快照并经用户授权，不自动覆盖真实资料。没有独立备份/恢复系统或Markdown导出PDF。
