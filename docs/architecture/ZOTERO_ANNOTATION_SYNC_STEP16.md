# Step16：Zotero标准批注双向同步

本轮v4.2.7，前置v4.2.6已正式发布并完成321附件匿名校验及45旧Release审计。只同步Zotero标准批注，继续禁用未经验证类型的写入；不处理ResearchClip私有手写或Markdown自动写回。复用现有ZoteroClient、受控授权、来源身份、PDF原件校验、任务所有权、只读Repository和缓存。

## 接口与状态

2026-10-27重新读取安装包，仍为Zotero10.0.6/Build20261007153950。核对[Local API](https://www.zotero.org/support/dev/web_api/v3/local_api)、[条件写入](https://www.zotero.org/support/dev/web_api/v3/write_requests)及[同步协议](https://www.zotero.org/support/dev/web_api/v3/syncing)。继续以本机对象版本及If-Unmodified-Since-Version保证条件写入；不把本机版本当作云端版本。默认复用完整、有界的附件批注读取，截断列表不能证明某项已删除。写入前逐项读取并核对完整身份；删除完成必须复读404。无新第三方依赖。

状态固定为SYNCED、LOCAL_DIRTY、REMOTE_CHANGED、CONFLICT、FAILED、READ_ONLY。另用有界的提交/待复核标记表达长任务，不把请求已发出说成已同步。记录本地修改时间、远端观测时间、成功同步时间；远端真实修改时间如API未提供则显示未提供，不用本地时间冒充。

保留基线、当前本地输入和最新远端快照。相同原key始终与实例、library type/ID、父文献和附件一起使用。远端变化且存在不同本地意图时冲突；相同目标内容可判定收敛，无需重复写入。修改/删除冲突保留双方；远端已删与本地修改冲突不能静默重建。用户可明确采用远端、以当前远端版本重新应用本地，或把已删除目标的本地内容另存为新批注。

## 持久化与兼容

SQLite20增量事务迁移新增标准批注同步状态、不可变处理修订及每来源刷新设置；001–019不改。沿用升级前验证快照、失败回滚和未来schema拒绝写入，不触碰真实用户数据库。只读缓存仍是原有远端投影，新增数据仅承载待处理意图、冲突依据和同步元数据，不建立第二套Markdown或PDF存储服务。复用既有32位资源ID生成及RevisionMetadata，不另建全局ID系统，不混入截图修订数据。

新建Zotero批注的外部8位key在首次安全落盘时固定；重试和进程重启复用相同key与version0条件，防止重复创建。发送前先持久记录意图与提交标记；连接中断或程序重启后先按该key读取核实，再决定是否允许条件重试。密钥仍仅留Rust内存，不入SQLite、修订、布局、日志或前端。所有失败保留待处理输入，解决冲突前将旧输入存入独立修订；不静默清空。

本地草稿编辑采用CAS修订号，防止迟到操作覆盖新内容。普通键入只更新当前本地草稿，不为每次轮询/按键无限堆积修订；提交、失败、冲突解决等边界保留不可变快照。队列和修订设容量保护，达到预算时拒绝覆盖并保留现有数据及当前未落盘输入。关闭须完成本地落盘；已落盘但未同步的修改允许下次恢复，不能把“保存到本地”显示成“已写入Zotero”。

## 操作与权限

手动同步先读取/比较，再提交已授权、无冲突的待处理项；远端只有变化时可只读接受。自动刷新默认关闭，可选30/60/300秒，只有GET，不自动申请授权或提交修改；忙碌/隐藏/销毁时正确停止或跳过，复用现有任务预算，不启动后台服务。

区分用户库与群组库及每项权限结果，不能仅凭群组类型推断可写或只读。401需要用户主动重新授权，403保留修改并标记READ_ONLY及原因；非作者、外部或库权限由Zotero权威检查。库/实例/PDF摘要变化停止写入，原件移动可经既有重新选择/关联流程恢复，不猜测或修改原PDF。

## 本轮实现与已取得的证据

实际实现保持一个新增main-only类型IPC、每PDF的原有Writer与Repository，不新增全局状态框架。SQLite20三表保存当前意图、独立处理修订与每来源设置；密钥仍只在ZoteroSessions内存。前端约180ms合并落盘和关闭前flush，CAS与输入代次保护迟到响应；本地未完成文本可存，发送前严格完整校验。冲突解决重新读取目标并验证显示版本，采用本地只重新排队；远端已删除时要求显式采用删除或复制后新建，不能自动复活。

独立真实Zotero10.0.6通过产品Rust客户端完成两个客户端同基线竞争、删除/修改竞争、固定key复核、重复创建拒绝和原PDF摘要不变。实际差异：目标在准备后被删除时PATCH可返回400；只有另行受控读取确认404才转换为目标删除冲突，不把其他400参数错误伪装成删除。Windows原生界面已完成模拟官方HTTP边界的状态/冲突/修订/断线/真实进程重启/布局22检查；真实授权GUI、群组和非作者策略不由此证明。最终完整检查与发布回执见本版验收记录。
