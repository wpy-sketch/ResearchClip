# v4.2.1：PDF清晰显示、Zotero配置与响应布局

本轮仅修复和完善现有PDF/Zotero使用、布局、指南与图标并发布4.2.1，不进入Step12。不增加应用依赖，SQLite保持16；001–016迁移不改，没有资料迁移或重置。

## 先行诊断与设计

现有Page把每页画布压至100万像素，放大时仍拉伸该画布；这是显示降采样，导入PDF原件与副本的SHA不变。采用现有PDF.js6.4.299与会话渲染队列，按可见区域生成最多1024×1024物理像素的图块，使用当前DPR及CSS显示比例重新绘制。滚动只绘制接近视口的图块，离开即释放；不把整页高倍图放进内存，不把低分辨率整页图拉伸成高清。

另外查到PDF.js解码重采样阈值原设16MiB（约4M像素），本版匹配既有32M像素上限改为128MiB；支持范围内的原图不再因该较小阈值被缩小。主视图与缩略图共享页资源租约，仅最后可见使用者离开才cleanup，避免每块重复解码。

单会话24M、全局72M RGBA像素预算（约96/288MB，非整个解析器堆上限），单图块1048576像素。PDF原件不重采样、不改页结构；文字层继续使用现有PDF.js TextLayer。显示旋转、窗口尺寸、DPR和界面缩放变更时重新测量可见区域；预算不足明确失败，不能偷偷把图块降采样。原PDF内部低清扫描和超过解码保护预算的图像不能凭空恢复细节。

Zotero复用现有只读客户端/取消会话，增加主窗口限定配置说明与独立连接检查。用户可复制正在运行的程序路径，在Zotero自选外部阅读器；API固定loopback23119，明确只读不需API key，不加任意URL/云密钥入口，不改真实Zotero设置或SQLite。连接检查与PDF来源查询相互独立；关闭取消任务，失败保留普通PDF阅读。

布局延续FlexLayout与原状态，使用容器断点、自然换行、收起次级工具、窄屏上下导航及rem字体响应。保持没有Markdown时无空白分栏。图标重设计为原创多色论文页与回形夹轮廓，SVG源与原生图标一起更新，不复刻Google商标。

## 验证

增加图块几何/DPR/高倍/旋转与预算边界测试；Windows原生对照PDF.js直接裁片像素，检查缩放后重绘、缓存释放与原件SHA。Zotero独立测试连接、403/离线/取消、外部路径/单实例和来源持久化；真实Zotero UI需实际授权和观察，不以HTTP模拟冒充。全部程序首/次进程均显式继承同一隔离目录，前后只读核对默认AppData摘要。发布需继承40版2575原附件，最终291附件全部匿名下载核对。

依据：[PDF.js HiDPI示例](https://mozilla.github.io/pdf.js/examples/)、[Zotero Local API](https://www.zotero.org/support/dev/web_api/v3/local_api)、[外部阅读器](https://www.zotero.org/support/pdf_reader)。
